# 🔷 Abstraction in Java

**Abstraction** means **hiding implementation details and showing only the essential features** to the user.

### Simple definition

> **Abstraction = What to do, but not how to do it.**

For example, when you use an ATM:

```text
You → Enter PIN → Withdraw Money
```

You know **what** the ATM does, but you don't need to know the internal code, database operations, or banking server communication.

---

# 🔷 Real-Life Example

Consider a **car**.

You know:

```text
Start the car
Accelerate
Brake
Change gear
```

But you don't need to know exactly how the engine internally works.

```text
          Car
           │
    ┌──────┼──────┐
    ↓      ↓      ↓
  Start  Brake  Accelerate
    │      │      │
    └──────┴──────┘
       Hidden
    implementation
```

This is **abstraction**.

---

# 🔷 Abstraction in Java

Java provides abstraction mainly using:

```text
Abstraction
    │
    ├── Abstract Class
    │
    └── Interface
```

---

# 1. 🔷 Abstract Class

An **abstract class** is a class declared using the `abstract` keyword.

```java
abstract class Animal {

}
```

You **cannot create an object directly** from an abstract class.

```java
Animal a = new Animal();  // ❌ Error
```

---

# 🔷 Abstract Method

An abstract method is a method that has **no body**.

```java
abstract void sound();
```

The child class must provide the implementation.

---

## ✅ Complete Example

```java
abstract class Animal {

    // Abstract method
    abstract void sound();

    // Normal method
    void eat() {
        System.out.println("Animal eats");
    }
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}

public class Main {

    public static void main(String[] args) {

        Dog dog = new Dog();

        dog.sound();
        dog.eat();
    }
}
```

### Output

```text
Dog barks
Animal eats
```

---

# 🔍 Step-by-Step

### Step 1: Abstract class

```java
abstract class Animal {
```

`Animal` is an abstract class.

---

### Step 2: Abstract method

```java
abstract void sound();
```

We are saying:

> Every Animal should have a `sound()` method, but we don't specify how it should work.

---

### Step 3: Child class

```java
class Dog extends Animal {
```

`Dog` inherits from `Animal`.

---

### Step 4: Implement the abstract method

```java
void sound() {
    System.out.println("Dog barks");
}
```

Dog provides its own implementation.

```text
Animal
  │
  └── sound() → What to do
                  ↓
                 Dog
                  ↓
             "Dog barks"
```

---

# 🔥 Why Can't We Create an Abstract Class Object?

This is invalid:

```java
abstract class Animal {
    abstract void sound();
}

public class Main {

    public static void main(String[] args) {

        Animal a = new Animal(); // ❌ Error
    }
}
```

Because the abstract class may contain methods whose implementation is incomplete.

Instead:

```java
Animal a = new Dog();
```

is valid.

```java
abstract class Animal {

    abstract void sound();
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}
```

Then:

```java
Animal a = new Dog();
a.sound();
```

Output:

```text
Dog barks
```

This also demonstrates **runtime polymorphism**.

---

# 🔷 Abstract Class Can Have Normal Methods

An abstract class does **not** mean that every method must be abstract.

It can contain:

* Abstract methods
* Normal methods
* Variables
* Constructors
* Static methods
* Final methods

Example:

```java
abstract class Animal {

    String name = "Animal";

    abstract void sound();

    void eat() {
        System.out.println("Eating...");
    }
}
```

So:

```text
Abstract Class
│
├── Abstract method
├── Normal method
├── Variables
├── Constructor
├── Static method
└── Final method
```

# 🔷 2. Interface

An **interface** is another way to achieve abstraction.

Example:

```java
interface Animal {

    void sound();
}
```

A class implements the interface:

```java
class Dog implements Animal {

    @Override
    public void sound() {
        System.out.println("Dog barks");
    }
}
```

Complete example:

```java
interface Animal {

    void sound();
}

class Dog implements Animal {

    @Override
    public void sound() {
        System.out.println("Dog barks");
    }
}

public class Main {

    public static void main(String[] args) {

        Animal animal = new Dog();

        animal.sound();
    }
}
```

### Output

```text
Dog barks
```

# 🔷 Abstract Class vs Interface

This is a **very common interview question**.

| Feature              | Abstract Class              | Interface                                   |
| -------------------- | --------------------------- | ------------------------------------------- |
| Keyword              | `abstract class`            | `interface`                                 |
| Inheritance keyword  | `extends`                   | `implements`                                |
| Object creation      | ❌ No                        | ❌ No                                        |
| Abstract methods     | ✅ Yes                       | ✅ Yes                                       |
| Normal methods       | ✅ Yes                       | ✅ Yes, with modern Java rules               |
| Variables            | Instance variables possible | Fields are constants                        |
| Constructor          | ✅ Yes                       | ❌ No                                        |
| Multiple inheritance | ❌ Class extends one class   | ✅ A class can implement multiple interfaces |

---

# 🔥 Example: Abstract Class

```java
abstract class Vehicle {

    abstract void start();

    void stop() {
        System.out.println("Vehicle stopped");
    }
}

class Car extends Vehicle {

    @Override
    void start() {
        System.out.println("Car starts with key");
    }
}
```

---

# 🔥 Example: Interface

```java
interface Vehicle {

    void start();
}

class Car implements Vehicle {

    @Override
    public void start() {
        System.out.println("Car starts with key");
    }
}
```
