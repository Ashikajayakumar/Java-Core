# 🔷 What is **Encapsulation**?

**Encapsulation** is the process of **wrapping data (variables) and code (methods)** together into a **single unit (class)**.

👉 It is also known as **data hiding**

---

## ✅ Simple Definition (Exam)

👉 **Encapsulation = binding data + methods together and restricting direct access**

---

## 🔷 Real-Life Example

💊 Capsule:

* Contains **different medicines inside**
* You only use it, don’t see inside

👉 Same in Java:

* Data is hidden
* Access given through methods

---

# 🔷 Why Encapsulation?

* **Data Security (Data Hiding)**
* **Control over data**
* **Improves flexibility**
* **Easy maintenance**
* Prevents **unauthorized access**

---

# 🔷 How to Achieve Encapsulation?

👉 3 steps:

1. Make variables **private**
2. Provide **public getter and setter methods**
3. Access data using these methods

---

## ✅ Example

```java id="p9n7gk"
class Student {
    private int id; // private variable

    // setter method
    public void setId(int id) {
        if (id > 100) {
            this.id = id;
        }
    }

    // getter method
    public int getId() {
        return id;
    }
}
```

---

## 🔥 Usage

```java id="b8g1zf"
public class Main {
    public static void main(String[] args) {
        Student s = new Student();

        s.setId(150); // valid
        System.out.println(s.getId());
    }
}
```

---

# 🔷 Advantages of Encapsulation

✔ Can make class:

* **Read-only** → only getter
* **Write-only** → only setter

✔ Add **validation logic**

✔ Improves **security**

---

# 🔷 Encapsulation + Access Modifiers

👉 Encapsulation uses **access modifiers**:

| Modifier      | Access Level       |
| ------------- | ------------------ |
| **private**   | Only within class  |
| **default**   | Within package     |
| **protected** | Package + subclass |
| **public**    | Everywhere         |
