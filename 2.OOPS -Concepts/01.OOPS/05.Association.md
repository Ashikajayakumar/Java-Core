# 🔷 Association in Java 

**Association** means a relationship between two classes.

In simple words:

> **Association = One object is connected to or uses another object.**

For example:

```text
Student ─────── Address
   │
   └── has an Address
```

There are two important special types of association:

```text
Association
    │
    ├── Aggregation → Weak HAS-A relationship
    │
    └── Composition → Strong HAS-A relationship
```

---

# 1. 🔷 Aggregation — Weak HAS-A Relationship

### Meaning

Aggregation means:

> **One class HAS-A reference to another class, but both objects can exist independently.**

For example:

```text
Student ─────── Address
```

A student has an address.

But the `Address` can exist even if the `Student` object is deleted.

---

## Complete Example

```java
class Address {

    String city;

    Address(String city) {
        this.city = city;
    }

    void displayAddress() {
        System.out.println("City: " + city);
    }
}

class Student {

    String name;
    Address address;

    Student(String name, Address address) {
        this.name = name;
        this.address = address;
    }

    void displayStudent() {
        System.out.println("Student Name: " + name);
        address.displayAddress();
    }
}

public class Main {

    public static void main(String[] args) {

        // Create Address object
        Address addr = new Address("Trichy");

        // Pass Address object to Student
        Student student = new Student("Ashika", addr);

        // Display student details
        student.displayStudent();
    }
}
```

### Output

```text
Student Name: Ashika
City: Trichy
```

---

## Step-by-Step Understanding

### Step 1: Create Address

```java
Address addr = new Address("Trichy");
```

An `Address` object is created independently.

```text
addr
 ↓
Address object
city = "Trichy"
```

---

### Step 2: Create Student

```java
Student student = new Student("Ashika", addr);
```

We pass the existing `Address` object to the `Student`.

```text
student
   ↓
Student object
   │
   ├── name = "Ashika"
   │
   └── address ──────→ Address object
                       city = "Trichy"
```

The `Student` does **not create** the Address.

It receives an already existing Address object.

---

### Step 3: Student Uses Address

```java
address.displayAddress();
```

The Student can use the Address object.

---

## Why is it Aggregation?

Because the two objects can exist independently.

```java
Address addr = new Address("Trichy");
```

Even without creating a Student, the Address exists.

```java
Address addr = new Address("Trichy");

Student student = new Student("Ashika", addr);
```

Now both objects exist.

If the Student object is no longer used:

```text
Student ❌
   ↓
Address ✓
```

The Address can still exist independently.

### Real-world example

```text
University ─────── Student
```

A student can exist independently of a particular university object.

Other examples:

```text
Department ─────── Teacher
Team ───────────── Player
Library ────────── Book
Student ────────── Address
```

---

# 2. 🔷 Composition — Strong HAS-A Relationship

Composition means:

> **One class strongly owns another object.**

The contained object is created **inside** the containing class.

For example:

```text
Car
 │
 └── Engine
```

A car **has an engine**.

In our Java example, the `Car` creates its own `Engine`.

---

## Complete Example

```java
class Engine {

    void start() {
        System.out.println("Engine started");
    }
}

class Car {

    private Engine engine;

    Car() {
        engine = new Engine();
    }

    void startCar() {
        engine.start();
        System.out.println("Car started");
    }
}

public class Main {

    public static void main(String[] args) {

        Car car = new Car();

        car.startCar();
    }
}
```

### Output

```text
Engine started
Car started
```

---

## Step-by-Step Understanding

### Step 1: Create Car

```java
Car car = new Car();
```

The `Car` constructor executes:

```java
Car() {
    engine = new Engine();
}
```

So the Car creates its own Engine.

```text
car
 ↓
Car object
 │
 └── engine
       ↓
     Engine object
```

---

### Step 2: Start the Car

```java
car.startCar();
```

Inside:

```java
void startCar() {
    engine.start();
    System.out.println("Car started");
}
```

First the Engine starts:

```java
engine.start();
```

Then the Car starts.

---

# Why is it Composition?

The important point is:

```java
class Car {

    private Engine engine;

    Car() {
        engine = new Engine();
    }
}
```

The `Car` itself creates the `Engine`.

The Engine is strongly associated with that Car.

Conceptually:

```text
Car
 │
 └── Engine
```

The Engine belongs to that Car.

---

# 🔥 Aggregation vs Composition

This is the most important part to understand.

## Aggregation

```java
Address addr = new Address("Trichy");

Student student = new Student("Ashika", addr);
```

The Address is created **outside** the Student.

```text
Address
   ↑
   │ passed into
   │
Student
```

So:

```text
Student ─────→ Address
```

Both can exist independently.

---

## Composition

```java
class Car {

    private Engine engine;

    Car() {
        engine = new Engine();
    }
}
```

The Engine is created **inside** the Car.

```text
Car
 │
 └────→ Engine
```

The Car strongly owns the Engine.

---

# 🔷 Side-by-Side Example

### Aggregation

```java
class Address {

    String city;

    Address(String city) {
        this.city = city;
    }
}

class Student {

    Address address;

    Student(Address address) {
        this.address = address;
    }
}
```

Creation:

```java
Address address = new Address("Trichy");

Student student = new Student(address);
```

Notice:

```java
new Address(...)
```

is outside `Student`.

---

### Composition

```java
class Engine {

}

class Car {

    Engine engine;

    Car() {
        engine = new Engine();
    }
}
```

Notice:

```java
new Engine()
```

is inside `Car`.

---

# ⭐ Easy Trick to Remember

Look at **where the object is created**.

### Aggregation

```java
Address address = new Address();
Student student = new Student(address);
```

Object created **outside** → **Aggregation**

### Composition

```java
class Car {

    Engine engine = new Engine();
}
```

Object created **inside** → **Composition**

---

# 🔷 Real-World Analogy

### Aggregation

Think about:

```text
Student ─────── Address
```

A student has an address.

The address doesn't necessarily depend on the Student object.

```text
Student ❌
   │
   X
   │
Address ✓
```

The Address can still exist.

---

### Composition

Think about:

```text
Car
 │
 └── Engine
```

The Engine is treated as a component owned by the Car.

```text
Car
 │
 └── Engine
```

When the Car's lifecycle ends, its owned Engine is considered part of that Car's lifecycle.
