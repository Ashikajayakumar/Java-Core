# 🔷 Polymorphism in Java

**Polymorphism** means **"many forms."**

In Java:

> **The same method name or action can behave differently depending on the situation.**

There are two main types:

```text
Polymorphism
│
├── 1. Compile-Time Polymorphism
│       └── Method Overloading
│
└── 2. Runtime Polymorphism
        └── Method Overriding
```

---

# 1. 🔷 Compile-Time Polymorphism

### Method Overloading

Method overloading means:

> **Multiple methods have the same name but different parameter lists.**

The compiler decides which method to call based on the arguments.

---

## ✅ Complete Example

```java
class MathUtil {

    // Method 1: two parameters
    int add(int a, int b) {
        return a + b;
    }

    // Method 2: three parameters
    int add(int a, int b, int c) {
        return a + b + c;
    }

    // Method 3: different parameter type
    double add(double a, double b) {
        return a + b;
    }
}

public class Main {

    public static void main(String[] args) {

        MathUtil obj = new MathUtil();

        // Calls add(int, int)
        int result1 = obj.add(10, 20);

        // Calls add(int, int, int)
        int result2 = obj.add(10, 20, 30);

        // Calls add(double, double)
        double result3 = obj.add(10.5, 20.5);

        System.out.println("Result 1 = " + result1);
        System.out.println("Result 2 = " + result2);
        System.out.println("Result 3 = " + result3);
    }
}
```

### Output

```text
Result 1 = 30
Result 2 = 60
Result 3 = 31.0
```



> **Method Overloading = Compile-Time Polymorphism**

---

# 🔷 Rules of Method Overloading

Methods must differ in their **parameter list**.

### ✅ Different number of parameters

```java
add(int a, int b)
add(int a, int b, int c)
```

### ✅ Different parameter types

```java
add(int a, int b)
add(double a, double b)
```

### ✅ Different order of parameter types

```java
display(int a, double b)
display(double a, int b)
```

---

## ❌ Return Type Alone Cannot Overload

This is invalid:

```java
class Demo {

    int add(int a, int b) {
        return a + b;
    }

    double add(int a, int b) {
        return a + b;
    }
}
```

### Why?

Both methods have exactly the same method signature:

```text
add(int, int)
```

The return type is different, but that is **not enough** for method overloading.

So this produces a compilation error.

---

# 🔷 Can We Overload `main()`?

Yes.

```java
class Main {

    public static void main(String[] args) {
        System.out.println("JVM calls this method");
    }

    public static void main(int number) {
        System.out.println("Overloaded main method");
    }
}
```

### Output

```text
JVM calls this method
```

The JVM specifically looks for:

```java
public static void main(String[] args)
```

The other `main()` is simply an overloaded method.

You could call it yourself:

```java
main(10);
```

# 2. 🔷 Runtime Polymorphism

### Method Overriding

Method overriding happens when:

> **A child class provides its own implementation of a method that already exists in the parent class.**

Requirements:

* Inheritance is required
* Same method name
* Same parameters
* Child provides a new implementation
* Method selection happens at runtime

---

# ✅ Complete Example

```java
class Animal {

    void sound() {
        System.out.println("Animal makes a sound");
    }
}

class Dog extends Animal {

    @Override
    void sound() {
        System.out.println("Dog barks");
    }
}

class Cat extends Animal {

    @Override
    void sound() {
        System.out.println("Cat meows");
    }
}

public class Main {

    public static void main(String[] args) {

        Animal animal1 = new Dog();
        Animal animal2 = new Cat();

        animal1.sound();
        animal2.sound();
    }
}
```

### Output

```text
Dog barks
Cat meows
```

---

# 🔍 How Runtime Polymorphism Works

Look carefully at:

```java
Animal animal1 = new Dog();
```

The **reference type** is:

```text
Animal
```

But the **actual object** is:

```text
Dog
```

When we call:

```java
animal1.sound();
```

Java checks the actual object at runtime.

```text
animal1
   ↓
Dog object
   ↓
Dog's sound()
   ↓
"Dog barks"
```

Similarly:

```java
Animal animal2 = new Cat();

animal2.sound();
```

The actual object is `Cat`, so:

```text
animal2
   ↓
Cat object
   ↓
Cat's sound()
   ↓
"Cat meows"
```

This is why it is called:

> **Runtime Polymorphism / Dynamic Method Dispatch**

# 🔷 3. Covariant Return Type

A **covariant return type** allows an overriding method in the child class to return a **more specific type** than the parent method.

## ✅ Complete Example

```java
class A {

    A get() {
        return this;
    }
}

class B extends A {

    @Override
    B get() {
        return this;
    }
}

public class Main {

    public static void main(String[] args) {

        B obj = new B();

        B result = obj.get();

        System.out.println("Object returned: " + result.getClass().getSimpleName());
    }
}
```

### Output

```text
Object returned: B
```

Parent:

```java
A get()
```

Child:

```java
B get()
```

Since `B` is a subclass of `A`, this is allowed.

```text
A
↑
B
```

So:

```text
Parent → A
Child  → B
```

is a **covariant return type**.

# 🔷 4. `super` Keyword

`super` refers to the **immediate parent class**.

It is commonly used to:

1. Call parent method
2. Access parent variable
3. Call parent constructor

---

## ✅ Complete Example — Calling Parent Method

```java
class A {

    void show() {
        System.out.println("Parent class");
    }
}

class B extends A {

    @Override
    void show() {

        // Call parent method
        super.show();

        // Child implementation
        System.out.println("Child class");
    }
}

public class Main {

    public static void main(String[] args) {

        B obj = new B();

        obj.show();
    }
}
```

### Output

```text
Parent class
Child class
```

Without:

```java
super.show();
```

only:

```text
Child class
```

would be printed.

---

# 🔷 `super` — Parent Variable

```java
class A {

    int number = 10;
}

class B extends A {

    int number = 20;

    void display() {

        System.out.println("Child = " + number);
        System.out.println("Parent = " + super.number);
    }
}

public class Main {

    public static void main(String[] args) {

        B obj = new B();

        obj.display();
    }
}
```

### Output

```text
Child = 20
Parent = 10
```

Here:

```java
number
```

means the child variable.

While:

```java
super.number
```

means the parent variable.

# 🔷 5. Instance Initializer Block

An **instance initializer block** is a block of code that executes when an object is created.

Syntax:

```java
{
    // instance initializer block
}
```

It runs **before the constructor**.

---

## ✅ Complete Example

```java
class Test {

    // Instance initializer block
    {
        System.out.println("Instance initializer block");
    }

    // Constructor
    Test() {
        System.out.println("Constructor");
    }
}

public class Main {

    public static void main(String[] args) {

        Test obj = new Test();
    }
}
```

### Output

```text
Instance initializer block
Constructor
```



### Output

```text
Instance block
Constructor
---
Instance block
Constructor
```

Because two objects were created:

```java
Test obj1 = new Test();
Test obj2 = new Test();
```


```

### ⭐ Most important examples to practice

**Overloading:**

```java
add(10, 20);
add(10, 20, 30);
```

**Overriding:**

```java
Animal a = new Dog();
a.sound();
```

The first is decided by the **compiler**; the second is decided by the **actual object at runtime**.
