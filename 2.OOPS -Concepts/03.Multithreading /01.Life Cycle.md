 # 🔷 Multithreading in Java — Detailed Explanation

Your notes are a good starting point. One **important correction** first:

> In modern Java terminology, `RUNNING` is **not a separate official `Thread.State`**. Java has 6 states: `NEW`, `RUNNABLE`, `BLOCKED`, `WAITING`, `TIMED_WAITING`, and `TERMINATED`.

We can still use **"running"** conceptually to understand what the CPU is doing.

---

# 🔹 1. What is Multithreading?

**Multithreading** means executing multiple threads concurrently within a single program/process.

### First understand Process

A **process** is a program that is currently executing.

For example:

```text
Chrome
   ↓
Process

VS Code
   ↓
Process

Spotify
   ↓
Process
```

Each process generally has its **own memory space**.

### Thread

A thread is a **path of execution inside a process**.

For example:

```text
Java Application
       |
       +---- Thread 1 → Download file
       |
       +---- Thread 2 → Play music
       |
       +---- Thread 3 → Handle user input
```

So:

> **Process = container**
> **Thread = execution path inside the container**

---

# 🔹 2. Why Do We Need Multithreading?

Suppose a program has only one thread:

```text
Task 1 → Task 2 → Task 3
```

If Task 1 takes a long time, Task 2 and Task 3 must wait.

With multiple threads:

```text
Thread 1 → Task 1
Thread 2 → Task 2
Thread 3 → Task 3
```

They can make progress concurrently.

### Real-life example

Think about a restaurant.

### Without multithreading

One employee does everything:

```text
Take order
   ↓
Prepare food
   ↓
Serve food
   ↓
Take next order
```

Very slow.

### With multithreading

```text
Employee 1 → Take orders
Employee 2 → Prepare food
Employee 3 → Serve food
```

Multiple activities can progress at the same time.

---

# 🔷 3. Multitasking Types

There are two major concepts you should know.

## 1️⃣ Process-based multitasking

Also called **multiprocessing** in general terminology.

Multiple processes execute independently.

```text
Computer
   |
   +---- Chrome
   |
   +---- VS Code
   |
   +---- Spotify
```

Each application is a separate process.

### Characteristics

* Separate memory spaces
* More resource usage
* Process communication is comparatively expensive
* Strong isolation between processes

---

# 🔹 2️⃣ Thread-based multitasking

This is **multithreading**.

Multiple threads execute inside one process.

```text
Java Application
       |
       +---- Thread 1
       +---- Thread 2
       +---- Thread 3
```

Threads of the same process can share memory.

### Characteristics

* Lightweight compared with processes
* Shared memory
* Communication can be easier
* Less overhead than creating separate processes

---

# 🔷 4. Process vs Thread

| Process                                  | Thread                                        |
| ---------------------------------------- | --------------------------------------------- |
| Independent program execution            | Execution path inside a process               |
| Has its own process memory space         | Threads share process memory                  |
| Heavyweight                              | Lightweight                                   |
| Communication is comparatively expensive | Communication is easier through shared memory |
| Creating process is more expensive       | Creating thread is comparatively cheaper      |

### Simple interview answer

> A process is an independent unit of execution, while a thread is a lightweight execution unit inside a process.

# 🔷 5. What is a Thread?

A **thread** is the smallest unit of execution that can be scheduled by the operating system/JVM.

For example:

```java
public class Main {
    public static void main(String[] args) {

        System.out.println("Hello");

    }
}
```

Even this program runs with a **main thread**.

You can see it:

```java
public class Main {
    public static void main(String[] args) {

        System.out.println(Thread.currentThread().getName());

    }
}
```

Typical output:

```text
main
```

So when Java starts your application:

```text
JVM
 |
 +---- main thread
```

# 🔷 6. Thread Life Cycle ⭐⭐⭐

This is extremely important for interviews.

The conceptual flow is:

```text
          NEW
           |
        start()
           ↓
       RUNNABLE
        /  |  \
       /   |   \
      ↓    ↓    ↓
 BLOCKED WAITING TIMED_WAITING
      \    |    /
       \   |   /
        ↓  ↓  ↓
       RUNNABLE
           |
       run() ends
           ↓
      TERMINATED
```

Java officially defines **6 thread states**.

```text
1. NEW
2. RUNNABLE
3. BLOCKED
4. WAITING
5. TIMED_WAITING
6. TERMINATED
```

# 🔹 7. NEW State

A thread enters the `NEW` state when its object is created but `start()` has not been called.

Example:

```java
Thread t = new Thread();
```

Flow:

```text
Thread object created
        ↓
       NEW
```

At this point the thread has **not started execution**.

You can check:

```java
System.out.println(t.getState());
```

Output:

```text
NEW
```

---

# 🔹 8. RUNNABLE State

When you call:

```java
t.start();
```

the thread becomes eligible for execution.

```text
NEW
 ↓
start()
 ↓
RUNNABLE
```

Example:

```java
Thread t = new Thread();

t.start();
```

### Important ⭐

Many beginners write:

```text
NEW → RUNNABLE → RUNNING
```

as if `RUNNING` were a separate Java state.

That's not technically correct.

Java's `Thread.State` has:

```text
RUNNABLE
```

which covers a thread that is **ready to run or actually running** from Java's state-model perspective.

The scheduler determines when it gets CPU time.

---

# 🔹 9. What happens when `start()` is called?

Suppose:

```java
Thread t = new Thread();
t.start();
```

Conceptually:

```text
Thread object
     ↓
    NEW
     ↓
   start()
     ↓
  RUNNABLE
     ↓
Scheduler gives CPU
     ↓
run() executes
```

### Very important

Never call:

```java
t.run();
```

when you want to create a new thread.

Instead:

```java
t.start();
```

### Difference

```java
t.run();
```

➡️ Normal method call.

```java
t.start();
```

➡️ Starts a new thread and eventually executes `run()`.

# 🔷 10. BLOCKED State

A thread becomes `BLOCKED` when it is waiting to acquire a **monitor lock**.

This commonly happens with `synchronized`.

Example:

```java
class Test {

    synchronized void display() {
        System.out.println("Hello");
    }
}
```

Suppose:

```text
Thread 1 → owns the lock
Thread 2 → wants the same lock
```

Then:

```text
Thread 1
   ↓
owns lock

Thread 2
   ↓
waiting for lock
   ↓
BLOCKED
```

When Thread 1 releases the lock:

```text
BLOCKED
   ↓
RUNNABLE
```

### Important

`BLOCKED` specifically means:

> Waiting to acquire a monitor lock.

It does **not** simply mean "waiting for anything."

---

# 🔷 11. WAITING State

A thread enters `WAITING` when it waits indefinitely for another thread to perform some action.

Common methods include:

```java
wait();
join();
```

For example:

```java
t1.join();
```

Suppose:

```text
Main Thread
     |
     | t1.join()
     ↓
  WAITING
```

The main thread waits until `t1` terminates.

Then:

```text
WAITING
   ↓
RUNNABLE
```

---

# 🔷 12. TIMED_WAITING State

A thread enters `TIMED_WAITING` when it waits for a **specific amount of time**.

Example:

```java
Thread.sleep(2000);
```

Flow:

```text
RUNNABLE
    ↓
sleep(2000)
    ↓
TIMED_WAITING
    ↓
2 seconds
    ↓
RUNNABLE
```

Other examples include:

```java
wait(2000);
join(2000);
```

### Difference

```text
WAITING
   ↓
Wait indefinitely
```

```text
TIMED_WAITING
   ↓
Wait for specified time
```

---

# 🔷 13. TERMINATED State

When the thread's execution is complete, it enters `TERMINATED`.

Example:

```java
class MyThread extends Thread {

    public void run() {
        System.out.println("Hello");
    }
}
```

After `run()` finishes:

```text
RUNNABLE
   ↓
run() completed
   ↓
TERMINATED
```

A terminated thread cannot be restarted.

```java
t.start();   // ✅

t.start();   // ❌
```

The second call throws:

```text
IllegalThreadStateException
```

# 🔷 14. Complete Life Cycle Example

Consider:

```java
class MyThread extends Thread {

    public void run() {

        System.out.println("Thread running");

        try {
            Thread.sleep(2000);
        } catch (InterruptedException e) {
            e.printStackTrace();
        }

        System.out.println("Thread finished");
    }
}
```

Main:

```java
public class Main {

    public static void main(String[] args) {

        MyThread t = new MyThread();

        System.out.println(t.getState());

        t.start();

        System.out.println(t.getState());

    }
}
```

Conceptually:

```text
             Thread object
                  ↓
                NEW
                  |
               start()
                  ↓
              RUNNABLE
                  |
             CPU execution
                  ↓
          Thread.sleep(2000)
                  ↓
          TIMED_WAITING
                  |
             2 seconds
                  ↓
              RUNNABLE
                  |
             run() ends
                  ↓
             TERMINATED
```

# 🔷 17. Thread vs Runnable ⭐⭐⭐

Your table has one point that should be corrected:

> `Runnable` itself doesn't create a thread. It represents the **task**, while `Thread` represents the execution mechanism/thread.

| Feature                 | `Thread`                      | `Runnable`            |
| ----------------------- | ----------------------------- | --------------------- |
| Type                    | Class                         | Functional interface  |
| Usage                   | `extends Thread`              | `implements Runnable` |
| Contains `run()`        | Yes                           | Yes                   |
| Creates thread?         | Yes, when `start()` is called | No, by itself         |
| Inheritance flexibility | Lower                         | Higher                |
| Recommended             | Usually less preferred        | Usually preferred     |
| Represents              | Thread + task                 | Task                  |

# 🔷 18. Why is Runnable Preferred?

This is an important interview question.

Suppose:

```java
class MyThread extends Thread {
}
```

Java does not support multiple class inheritance.

So you cannot do:

```java
class MyThread extends Thread, Employee {  // ❌
}
```

But with `Runnable`:

```java
class MyTask extends Employee implements Runnable {
}
```

This is possible.

Why?

Because Java allows:

```text
One parent class
+
Multiple interfaces
```

Therefore:

```text
extends Thread
      ↓
Uses your class inheritance

implements Runnable
      ↓
Keeps inheritance available
```

That's one major reason `Runnable` is preferred.

# 🔷 21. `start()` vs `run()` ⭐⭐⭐

This is one of the most common interview questions.

### `start()`

```java
t.start();
```

Creates a new execution path/thread and causes `run()` to execute on that thread.

### `run()`

```java
t.run();
```

Just executes the method like a normal method call on the current thread.

### Example

```java
class MyThread extends Thread {

    public void run() {
        System.out.println(Thread.currentThread().getName());
    }
}
```

If:

```java
MyThread t = new MyThread();

t.start();
```

Output might be:

```text
Thread-0
```

But:

```java
t.run();
```

Output:

```text
main
```

because `run()` was called directly by the main thread.

# 🔷 22. `join()` Method ⭐⭐⭐

`join()` means:

> **Wait for this thread to finish.**

Example:

```java
class MyThread extends Thread {

    public void run() {

        for(int i = 1; i <= 5; i++) {

            System.out.println(i);

            try {
                Thread.sleep(500);
            } catch (InterruptedException e) {
                e.printStackTrace();
            }
        }
    }
}
```

Main:

```java
public class Main {

    public static void main(String[] args) {

        MyThread t = new MyThread();

        t.start();

        try {
            t.join();
        } catch (InterruptedException e) {
            e.printStackTrace();
        }

        System.out.println("Main finished");
    }
}
```

Flow:

```text
Main Thread
     |
     | start t
     ↓
Thread t starts
     |
     | join()
     ↓
Main waits
     |
     ↓
t completes
     |
     ↓
Main continues
     |
     ↓
"Main finished"
```

Therefore output order is:

```text
1
2
3
4
5
Main finished
```

# 🔷 23. Why Does `join()` Put Main into WAITING?

When you write:

```java
t.join();
```

the **current thread** waits for `t`.

If the current thread is `main`:

```text
main
 ↓
t.join()
 ↓
WAITING
```

Meanwhile:

```text
t
 ↓
RUNNABLE
 ↓
run()
 ↓
TERMINATED
```

Then:

```text
main
 ↓
RUNNABLE
```

and it continues.

# 🔷 24. Two Threads Example

```java
class A extends Thread {

    public void run() {
        System.out.println("Thread A running");
    }
}

class B extends Thread {

    public void run() {
        System.out.println("Thread B running");
    }
}

public class Main {

    public static void main(String[] args) {

        A t1 = new A();
        B t2 = new B();

        t1.start();
        t2.start();
    }
}
```

Important:

The output is **not guaranteed** to be:

```text
Thread A running
Thread B running
```

It could also be:

```text
Thread B running
Thread A running
```

because the scheduler determines which runnable thread gets CPU time.

# 🔷 25. Thread Scheduler

The **thread scheduler** decides which runnable thread gets CPU time.

Suppose:

```text
Thread A → RUNNABLE
Thread B → RUNNABLE
Thread C → RUNNABLE
```

The scheduler decides execution order.

It could be:

```text
A → B → C
```

or:

```text
B → A → C
```

or:

```text
C → A → B
```

Therefore, don't assume thread execution order unless you explicitly synchronize it.

# 🔷 26. Multithreading Does NOT Always Mean Parallel Execution

This distinction is important.

### Concurrency

Multiple tasks make progress during overlapping periods.

### Parallelism

Multiple tasks literally execute at the same time, typically using multiple CPU cores.

For example:

```text
Single CPU core

Thread A → CPU
Thread B → CPU
Thread A → CPU
Thread B → CPU
```

The CPU switches between threads.

This is **concurrency**.

With multiple cores:

```text
Core 1 → Thread A
Core 2 → Thread B
```

They can execute truly in parallel.

# 🔷 27. `sleep()` vs `join()` ⭐⭐⭐

| `sleep()`                                  | `join()`                                     |
| ------------------------------------------ | -------------------------------------------- |
| Makes current thread wait                  | Makes current thread wait for another thread |
| Takes time as argument                     | Can be used with/without timeout             |
| `TIMED_WAITING`                            | `WAITING` without timeout                    |
| Does not wait for another thread to finish | Waits for specified thread to finish         |

Example:

```java
Thread.sleep(2000);
```
