# 🔷 Thread Scheduler in Java

---

## 🔹 What is Thread Scheduler?

The **Thread Scheduler** is a part of the JVM that decides:

👉 **Which thread will run next and for how long**, when multiple threads are in the **RUNNABLE state**.

✔ It selects one thread from the runnable pool and sends it to CPU for execution.

---

## 🔹 Important Point

⚠️ Java does NOT guarantee exact thread scheduling behavior.

It depends on:

* JVM implementation
* Operating System (Windows / Linux / Mac)

---

# 🔷 Thread Scheduling Algorithms

Java mainly uses **two scheduling techniques**:

---

# 1️⃣ Preemptive Scheduling

---

## 🔹 Concept:

* CPU is assigned to the **highest priority thread**
* If a higher priority thread arrives → it **preempts (interrupts)** the current thread

---

## 🔹 Example:

```java
Thread t1 = new Thread();
Thread t2 = new Thread();

t1.setPriority(2);
t2.setPriority(10);

t1.start();
t2.start();
```

---

## 🔹 Working:

* t2 (priority 10) has higher chance to run first
* t1 may be paused if t2 becomes ready

---

## 🔹 Key Points:

* ✔ Priority range: 1 to 10
* ✔ Default priority: 5
* ✔ Higher priority → more CPU chance
* ✔ Not guaranteed (only suggestion to JVM)

---

# 2️⃣ Time Slicing (Round Robin)

---

## 🔹 Concept:

* Each thread gets a **fixed time slice (CPU time)**
* After time expires → next thread gets CPU

---

## 🔹 Example:

```java
Thread t1 = new Thread();
Thread t2 = new Thread();

t1.start();
t2.start();
```

---

## 🔹 Working:

```
t1 → runs for some time
t2 → runs
t1 → runs again
t2 → runs again
```

---

## 🔹 Key Points:

* ✔ Ensures fairness
* ✔ No starvation
* ✔ Execution order is unpredictable

---

# 🔷 Working of Java Thread Scheduler

---

## 🔹 What it does:

The Thread Scheduler (inside JVM):

* ✔Part  of the JVM that **managaes execution of multiple threads**.
* ✔ Picks thread from **runnable pool**
* ✔ Allocates CPU times
* ✔ Performs context switching

---

## 🔹 Step-by-Step Working

---

### 1️⃣ Thread Creation

```java
Thread t1 = new Thread();
Thread t2 = new Thread();
```

👉 Both threads are in **NEW state**

---

### 2️⃣ start() method

```java
t1.start();
t2.start();
```

👉 Threads move to **RUNNABLE state**

---

### 3️⃣ Runnable Pool

All threads wait in a queue:

```
[t1, t2, t3]
```

---

### 4️⃣ Scheduler Selection

Scheduler chooses a thread based on:

✔ Priority
✔ Availability
✔ OS scheduling policy

---

### 5️⃣ Running State

Selected thread enters:

```
RUNNING state
```

---

### 6️⃣ Context Switching

Scheduler may switch threads due to:

✔ Time slice expiry
✔ Higher priority thread
✔ sleep(), yield(), wait()

---

### 7️⃣ State Changes

| Condition            | State         |
| -------------------- | ------------- |
| Waiting for lock     | BLOCKED       |
| Waiting indefinitely | WAITING       |
| Waiting with time    | TIMED WAITING |
| Execution completed  | TERMINATED    |

# 🔷 Important Thread Methods in Scheduling

## 🔹 sleep()

```java
Thread.sleep(1000);
```

👉 Pauses thread temporarily (TIMED WAITING)

---

## 🔹 yield()

```java
Thread.yield();
```

👉 Suggests scheduler to give chance to other threads

---

## 🔹 wait()

👉 Releases lock and waits

---

## 🔹 join()

```java
t1.join();
```

👉 Current thread waits for t1 to finish
