# 🔷 Thread Scheduler in Java 

---

## 🔹 What is Thread Scheduler?

The **Thread Scheduler** is a part of the JVM that decides:

👉 **Which thread will run next and for how long**

When multiple threads are in **RUNNABLE state**, the scheduler selects one thread for execution.

---

## 🔹 Why is it needed?

Because:

* CPU can execute only **one thread at a time per core**
* Multiple threads compete for CPU time
* Scheduler ensures **efficient CPU utilization**

---

## ⚠️ Important Point

👉 Java does **NOT guarantee exact thread execution order**

Execution depends on:

* JVM implementation
* Operating System (Windows/Linux/Mac)
* CPU architecture

---

# 🔷 Working of Thread Scheduler (Step-by-Step)

---

## 🔹 1️⃣ Thread Creation (NEW state)

```java
Thread t1 = new Thread();
Thread t2 = new Thread();
```

👉 Threads are in **NEW state**

---

## 🔹 2️⃣ Start Method

```java
t1.start();
t2.start();
```

👉 Threads move to **RUNNABLE state**

---

## 🔹 3️⃣ Runnable Pool (Ready Queue)

All threads enter a pool:

```
[t1, t2, t3, t4]
```

👉 Waiting for CPU allocation

---

## 🔹 4️⃣ Scheduler Selection

Scheduler selects a thread based on:

* Priority (1–10)
* CPU availability
* OS scheduling algorithm

👉 Example:

```
Selected → t2
```

---

## 🔹 5️⃣ Execution (RUNNING state)

```
t2 → RUNNING
```

Thread executes its `run()` method.

---

## 🔹 6️⃣ Context Switching

Scheduler may pause a thread and switch to another due to:

* Time slice completion
* Higher priority thread arrival
* `sleep()`, `yield()`, `wait()`, `join()`

---

## 🔹 7️⃣ Completion

Thread finishes execution:

```
RUNNING → TERMINATED
```

# 🔷 Scheduling Algorithms

---

## 🔹 1️⃣ Preemptive Scheduling (Priority Based)

### Concept:

* Higher priority thread gets CPU first
* Lower priority thread can be paused anytime

### Priority Range:

```
1 (MIN) → 10 (MAX)
Default = 5
```

### Example:

```java
t1.setPriority(Thread.MIN_PRIORITY);
t2.setPriority(Thread.MAX_PRIORITY);
```

### Key Idea:

👉 “Important tasks first”

---

## 🔹 2️⃣ Time Slicing (Round Robin)

### Concept:

* Each thread gets a small time slice
* CPU rotates between threads

### Key Idea:

👉 “Fair sharing of CPU”

### Output is unpredictable:

```
T1 → T2 → T1 → T2
```

---

# 🔷 Internal Working Example

```java
class MyThread extends Thread {
    public void run() {
        System.out.println(Thread.currentThread().getName() + " started");

        try {
            Thread.sleep(1000); // TIMED WAITING
        } catch (Exception e) {}

        System.out.println(Thread.currentThread().getName() + " finished");
    }
}

public class Main {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        MyThread t2 = new MyThread();

        t1.start();
        t2.start();
    }
}
```

---

## 🔍 What Scheduler Does Here:

1. Both threads → RUNNABLE
2. Scheduler picks one → RUNNING
3. Thread may sleep → TIMED WAITING
4. Scheduler switches to other thread
5. Execution continues

---

## 🔹 Output (NOT fixed)

```
Thread-0 started
Thread-1 started
Thread-1 finished
Thread-0 finished
```

# 🔷 Important Concepts

---

## 🔸 1. Context Switching

Switching CPU from one thread to another.

👉 Saves execution state and resumes later.

---

## 🔸 2. Runnable Pool

Queue where all ready threads wait.

---

## 🔸 3. Non-Deterministic Behavior

👉 You CANNOT predict thread order.

---

## 🔸 4. OS Dependency

Scheduler behavior depends on:

* Operating System
* JVM implementation

---

# 🔷 Thread Methods Related to Scheduling

| Method    | Purpose                                   |
| --------- | ----------------------------------------- |
| `sleep()` | Pause thread for time                     |
| `yield()` | Suggest scheduler to pause current thread |
| `join()`  | Wait for another thread                   |
