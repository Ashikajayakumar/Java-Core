
# 🔹 Java Non-Generic vs Generic Collection
## 🔹 Background     
      
* 👉 Before JDK 1.5, Java collections were **non-generic**     
* 👉 After JDK 1.5, **Generics** were introduced    
    
✔ This made collections **type-safe and more powerful**  
   
--- 
  
# 🔹 1️⃣ Non-Generic Collection  

### ✅ Concept

A collection that can store **any type of objects**

👉 No type restriction

### 💡 Example

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        ArrayList list = new ArrayList(); // Non-generic

        list.add(10);
        list.add("Java");
        list.add(3.14);

        System.out.println(list);
    }
}
```

👉 Output:

```
[10, Java, 3.14]
```

### ❌ Problems

* No type safety
* Runtime errors possible
* Requires type casting

```java
int num = (int) list.get(1); // Runtime error ❌
```



# 🔹 2️⃣ Generic Collection (Modern Approach)

### ✅ Concept

A collection that stores **only one specific type**

👉 Uses **Generics (`< >`)**

---

### 💡 Example

```java
import java.util.*;

public class Main {
    public static void main(String[] args) {
        ArrayList<String> list = new ArrayList<>(); // Generic

        list.add("Java");
        // list.add(10); ❌ Compile-time error

        System.out.println(list);
    }
}
```

👉 Output:

```
[Java]
```

---

### ✅ Advantages

* Type safety ✔️
* No casting required ✔️
* Errors detected at compile-time ✔️

---

# 🔹 Key Difference

| Feature     | Non-Generic           | Generic                   |
| ----------- | --------------------- | ------------------------- |
| Type Safety | ❌ No                  | ✅ Yes                     |
| Data Types  | Mixed (heterogeneous) | Single type (homogeneous) |
| Errors      | Runtime               | Compile-time              |
| Casting     | Required              | Not required              |
| Usage       | Old Java              | Modern Java ✔️            |
